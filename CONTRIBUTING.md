# Contributing to Elevator

Thank you for your interest in contributing to Elevator! Whether it's a bug
report, a new feature, a correction, or additional documentation, we greatly
value feedback and contributions from the community.

Please read through this document before submitting any issues or pull requests
to ensure we have all the information needed to respond effectively.

## Reporting Bugs / Feature Requests

Please use the GitHub issue tracker to report bugs or suggest features.

Before filing an issue, check existing open and recently closed issues to make
sure the problem hasn't already been reported. When you do open an issue, please
include as much detail as you can:

* A reproducible test case or series of steps
* The version (or commit) of Elevator you are using
* Any modifications you've made relevant to the bug
* Anything unusual about your environment or deployment

## Contributing via Pull Requests

Contributions via pull requests are much appreciated. Before sending a pull
request, please make sure that:

1. You are working against the latest source on the `main` branch.
2. You have checked existing open and recently merged pull requests to make sure
   someone else hasn't already addressed the problem.
3. You have opened an issue to discuss any significant work — we'd hate for your
   time to be wasted.

To send us a pull request, please:

1. Fork the repository.
2. Modify the source, focusing on the specific change you are contributing. If
   you also reformat all the code, it will be hard to review your change.
3. Ensure local checks pass (`npm run typecheck`, `npm run build`, and the
   backend tests under `lambda/backend/tests`).
4. Commit using clear, descriptive commit messages.
5. Open a pull request, describing the change and the motivation behind it.
6. Watch for automated CI results and stay engaged in the review conversation.

GitHub provides helpful guides on [forking a repository][fork] and
[creating a pull request][pr].

[fork]: https://help.github.com/articles/fork-a-repo/
[pr]: https://help.github.com/articles/creating-a-pull-request/

## Finding Contributions to Work On

Looking at the existing issues is a great way to find something to work on.
Issues labeled `help wanted` or `good first issue` are a good place to start.

## Security Issues

If you discover a potential security vulnerability, please **do not** open a
public GitHub issue. Instead, report it privately by emailing
**asyschikov@gmail.com** so it can be addressed before public disclosure.

## Code of Conduct

This project has adopted a [Code of Conduct](CODE_OF_CONDUCT.md). By
